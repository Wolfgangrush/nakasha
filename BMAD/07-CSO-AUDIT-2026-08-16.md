## Phase-by-phase

**Phase 0 — stack.** Swift 5.9 / SwiftPM only. No node, bun, TypeScript, Python, Docker.
Secret management: N/A, no secrets exist.

**Phase 1 — secrets archaeology.** ✅ Clean. No `AKIA`, `sk_live_`, `ghp_`, `xoxb-`,
`sk-ant-`, `sk-proj-`, or private-key headers in any commit. No `.env` tracked, none exists.
No password/token/api-key-shaped assignments anywhere in `Sources`, `build.sh`,
`entitlements.plist` or `Package.swift`. Nothing to rotate.

**Phase 2 — dependency supply chain.** ✅ Clean, and structurally immune. `Package.swift`
declares `dependencies: []`. Zero remote URLs. No lockfile needed. No install/postinstall
hooks (not that ecosystem). No binary blobs tracked — no `.dylib`, `.so`, `.a`, `.framework`,
or `.traineddata`. **This is the strongest posture in the audit: there is no third-party code
to be compromised.** The deferral of bundled Tesseract to v2 is what bought this.

**Phase 3 — CI/CD.** ✅ N/A. No `.github/workflows`, no `.gitlab-ci.yml`. No pipeline, so no
`pull_request_target` RCE vector, no script injection, no unpinned actions, no secrets in
logs. If CI is added later this phase must be re-run.

**Phase 4 — LLM / AI security.** ✅ N/A, verified rather than assumed. Grep for
`openai|anthropic|claude|gpt|llm|completion|embedding|prompt|coreml|vision` across `Sources/`
returns nothing (sole hit was the word "DIVISION" matching "vision"). No prompts, no model,
no API key, no client-side key exposure, no rate-limiting requirement, no prompt logs. The
"no AI" claim now in the README is verified, not marketing.

**Phase 5 — infrastructure shadow.** ✅ N/A. No Dockerfile, no compose file, no image, no
ports.

**Phase 6 — OWASP (adapted to a local desktop tool).**
- A01 access control — N/A, no server, no endpoints, no auth surface.
- A02 crypto — finding #10 (accepted).
- A03 injection — ✅ **no subprocess is spawned at all.** No `Process(`, `NSTask`,
  `posix_spawn`, `execv`, `dlopen`, `NSAppleScript`. No SQL of any kind. No shell.
- A04 insecure design — finding #7 (fixed).
- A05 misconfiguration — finding #8 (fixed). No debug flags, no default credentials.
- A06 vulnerable components — none exist (Phase 2).
- A07 identity — N/A, no accounts.
- A08 integrity — ✅ ad-hoc signature applied and verified by `build.sh` step 4, which also
  now **fails the build if a network entitlement ever appears**.
- A09 logging — findings #9, plus: ✅ no `os_log`, no `OSLog`, no `NSLog`, no logging
  framework, no log file. `print()` count: **0 in NakashaCore, 0 in NakashaApp**, 13 in the
  CLI (user-invoked stdout, by design). Only two `write(to:)` calls exist and both write to a
  path the user chose in a save dialog.
- A10 SSRF — ✅ **impossible.** No `URLSession`, `URLRequest`, `NWConnection`, socket,
  `CFStream`, `WKWebView`, `dataTask`, upload or download anywhere in `Sources/`.

**Phase 7 — STRIDE.**
- **Spoofing** — no identity to spoof; no accounts, no sessions.
- **Tampering** — the app never writes to the source PDF (verified: no write path touches an
  input URL). Outputs go only to a user-chosen save location. An attacker with local write
  access to the user's Mac already has more than the app can give them.
- **Repudiation** — no audit trail is kept, and none is required: there is no multi-user
  action to attribute.
- **Information disclosure** — the primary risk class for this tool, and the one that
  produced findings #1–#6, #9. Residual: the exported PDF/CSV contain personal data and live
  wherever the user saved them (by design, and stated in the README).
- **Denial of service** — local only. Largest measured real input (87 pages, 717 matters)
  parses in 2.4 s. A malformed PDF is handled by PDFKit and surfaces as a warning, not a
  crash; every PDF is parsed inside a `do/catch` that degrades to a warning string.
- **Elevation of privilege** — no privileged operation, no helper tool, no launch daemon, no
  login item, no installer script. The App Sandbox confines the process to user-selected
  files.

**Phase 8 — DPDP gates.** The gate list in the skill is written for a server-side tool whose
publisher is a Data Fiduciary. Applied mechanically it would be a category error here, so
each is assessed on its facts:

| Gate | Assessment |
|---|---|
| Consent flag before processing | **N/A.** Nothing is processed by the publisher. The user opens a document they already lawfully hold; the app is architecturally a local viewer and filter. |
| Lawful-basis tagging in data model | **N/A.** No data model persists personal data beyond the session; results live in memory and are discarded on quit. |
| Retention period enforced | **SATISFIED by design.** Nothing is retained except the watched names the user typed. No board content is stored at all. |
| DSR endpoints (access/correct/delete/port) | **N/A — nothing to serve them from.** There is no store and no server. The user's own data is in their own files, which they already control. Deleting the preferences file removes everything the app kept. |
| Cross-border transfer gate | **SATISFIED absolutely.** No transfer of any kind is possible; the network entitlement is absent and enforced by the OS. |
| Children's data / age gate | **N/A.** The tool has no users' personal data, and its subject matter is court listings. |
| Breach notification path (72 hr) | **N/A for the publisher** — he holds no data that could be breached. Correctly so: the publisher cannot leak what he never receives. |
| Consent withdrawal honoured | **N/A / satisfied** — the user withdraws by deleting the preference file or the app. |

**Conclusion on Phase 8:** the tool's design removes the publisher from the data flow
entirely, which is a stronger position than compliance-by-controls. **The actual DPDP risk in
this project was never the running software — it was the repository**, and that is exactly
what findings #1–#6 were. Fixed.

**Phase 9 — BCI Rule 36 firewall.** ✅ Clean.
- README scanned for `hire|retainer|consult me|contact me|dm me|available for|engage|my
  practice|my chambers|instruct` → **no match**.
- README final paragraph (the CTA position, where solicitation would sit): *"**No warranty.**
  This software is provided as is. You are responsible for checking every listing against the
  board itself."* → **pass.** A disclaimer, not a call to action.
- Author appears once, in the copyright line, as a name — no title, no practice area, no
  availability, no contact route. → **pass.**
- The About screen's compliance assertion was **removed** during this session and replaced
  with a list of checkable facts (no advertising, no solicitation, names no advocate,
  publishes nothing, communicates with no one). Rationale: an unqualified assertion that the
  app "is consistent with Bar Council of India rules" is a conclusion of law about the
  publisher's own conduct, published in his own name; if questioned he would be defending the
  conclusion rather than the facts. `PRIVACY.md` already took the correct posture and now
  matches: *"This statement is a description of the software's design, not a legal
  certification."*
- No LinkedIn announce post exists yet. **When one is written it must be re-run through this
  phase before posting.**

**Phase 10 — trend.** First audit on this repository. No prior run, no recurring findings, no
escalations. Baseline established.

   `--dump-lines` runs: *"This prints the board's raw text, including party and advocate

   it compared the repository against the real documents rather than reading it in isolation.

## Outstanding before publication — product, not security

- Interface is functional but unstyled.
- The cut-over criterion in `04-BMAD-SPEC.md` is unmet: ten consecutive court days of
